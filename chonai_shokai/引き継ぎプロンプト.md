# Claude Code 引き継ぎプロンプト

以下をそのまま Claude Code に貼り、同じディレクトリに `庁内照会アプリ_エンジン.html` を置いてください。

---

添付の `庁内照会アプリ_エンジン.html` を引き継いで開発してください。

## このツールの目的

自治体の庁内照会・回答業務を、単一HTMLファイルの配布だけで回すためのツールです。運用フローは次のとおりです。

1. 照会元課が「設計モード」で設問を組み立て、その照会専用のHTMLを書き出す
2. 照会元課 → 各部管理課 → 各課 へ、そのHTMLファイルを配布する
3. 各課は「回答モード」で回答を作成し、印刷/PDF化したものを別の決裁システムに添付して決裁を取る。あわせてCSVを書き出して各部管理課へ提出する
4. 各部管理課は「取りまとめモード」で各課のCSVをまとめて読み込み、1本のCSVに束ねて照会元課へ提出する

同じ1本のHTMLが、モード切替によって3つの役割を兼ねます。照会のたびにアプリを作り直さず、スキーマ(設問定義)を差し替えた自己複製ファイルを配る、という設計です。

## 絶対に守る制約

- **LGWAN(自治体の閉域網)内で使う。インターネット接続は一切ない。**
- **単一HTMLファイル完結。** 外部CDN・npmパッケージ・フォントの読み込み・ビルドツールはすべて不可。CSSもJSも同じファイル内にインラインで書く
- **`file://` プロトコルで直接開いて動くこと。** ローカルサーバは立てられない
  - File System Access API の書き込み(`showSaveFilePicker`)は `file://` では動かない。出力は必ず `Blob` + `<a download>`
  - 読み込みは `<input type="file">` を使う(複数ファイルは `multiple`)
  - `localStorage` / `sessionStorage` / `fetch` は使わない
- **想定ブラウザは Windows 上の Edge / Chrome。** システムフォントのみ使用(游明朝・游ゴシック・Meiryo など)
- **固有名詞(個人名・企業名・自治体名など)はすべて `〇〇` のプレースホルダにすること。** サンプルデータやプレースホルダ文言も同様
- UIの文言はすべて日本語。自治体職員が読んで迷わない、システム用語を避けた言い回しにする

## 現在の実装状況

実装済み:

- 3タブ構成(照会を設計 / 回答を作成 / 回答を取りまとめ)
- **設計モード** … 照会の基本情報と設問の編集(追加・並べ替え・複製・削除)、7種類の回答形式、必須指定、補足説明、選択肢。入力しながら回答画面の見え方をライブプレビュー
- **配布用ファイルの書き出し** … `document.documentElement.cloneNode(true)` を複製 → `[data-runtime]` 属性を持つ要素の中身を空にして初期状態へ戻す → `#inquiry-schema` の `<script type="application/json">` にスキーマJSONを埋め込む → Blobでダウンロード
- 書き出し前の検証(件名・照会番号の未入力、設問文の空欄と重複、選択肢型で選択肢なし)。通らないとボタンが押せない
- 設計データ(スキーマ)単体のJSON保存・読み込み
- **回答モード** … スキーマから回答フォームを描画。印刷/PDF用のCSS(操作UIを隠し、照会票の体裁だけをA4に出す)
- 起動時、スキーマに設問があれば「回答を作成」タブを、なければ「照会を設計」タブを開く

未実装:

- 回答モードのCSV書き出し・読み込み(下書きの再開)
- 回答モードの必須チェック
- 取りまとめモード全体(現在はプレースホルダの空画面)

## スキーマの形

`<script type="application/json" id="inquiry-schema">` にこの形で入ります。

```json
{
  "formatVersion": 1,
  "meta": {
    "inquiryId": "R08-〇〇-001",
    "title": "〇〇に関する調査について",
    "fromDept": "〇〇部〇〇課",
    "dueDate": "2026-09-30",
    "note": "該当がない場合も「該当なし」と記入のうえ提出してください。"
  },
  "items": [
    {
      "key": "q1",
      "label": "〇〇の実施状況",
      "type": "text",
      "required": true,
      "hint": "記入上の注意など",
      "options": []
    }
  ]
}
```

- `type` は `text` / `textarea` / `number` / `date` / `select` / `radio` / `checkbox`
- `options` は `select` / `radio` / `checkbox` のときだけ使う
- **`key` は一度振ったら変えない。** 設問を並べ替えても `q1` は `q1` のまま。CSVの列対応がこれで保たれる

## 次にやってほしいこと

### 1. 回答形式(単票/明細)の方針を先に確認する

1課あたりの回答が **1件だけ(単票)** か、**1課で複数行を書ける(明細)** かで、CSVの形も取りまとめロジックも変わります。「該当する業務をすべて挙げてください」型の照会だと明細が必要になります。

実装に入る前に、単票のみで進めるか、`meta` に `answerMode` を足して両対応にするかを確認してください。両対応にする場合、明細は「行を追加/削除できる表」として描画します。

### 2. 回答モードのCSV書き出し

- **UTF-8 BOM付き**(Excelでの文字化け防止)、改行は CRLF、`"` と `,` と改行を含む値はダブルクォートで囲む
- 1行目は見出し。列は最低限、照会番号 / 回答課名 / 提出日時 / 各設問(`key` 順)
- **回答課名の入力欄が回答モードに必要**(現在は照会票ヘッダーに空欄があるだけ)。ここが取りまとめ時の識別キーになるので必須にする
- 見出し行に `key` も持たせるか、`label` だけにするかは検討のうえ決めてください。取りまとめ側でスキーマと突き合わせるので、`key` を持つほうが安全です
- `checkbox` の複数選択値をどう1セルに入れるか(区切り文字)を決め、取りまとめ側と揃える
- 書き出し前に必須項目の未入力チェックを行い、未入力があれば該当設問を画面上で示す
- ファイル名は `回答_{照会番号}_{回答課名}.csv` の形

### 3. 回答モードのCSV読み込み(下書きの再開)

自分が書き出したCSVを読み戻してフォームに復元できるようにします。照会番号がスキーマと一致しない場合は、はっきりと理由を示して読み込みを中止してください。

### 4. 取りまとめモード

- `<input type="file" multiple>` で各課のCSVをまとめて読み込む
- 照会番号がスキーマと一致しないファイルは弾き、ファイル名と理由を一覧で示す
- 同じ課のCSVが重複していたら警告する(上書き事故の防止)
- 読み込んだ内容を課ごとの一覧表で画面に表示し、確認できるようにする
- 1本のCSVに束ねて書き出す(同じくUTF-8 BOM付き)。ファイル名は `取りまとめ_{照会番号}_{部名}.csv`
- **未提出課のチェック機能は今回は不要**(将来入れる可能性はあるので、設計の妨げにならないようにだけしておく)

## コードの流儀

- 既存のトークン(`:root` のCSS変数)と部品を必ず使い回す。特に `buildKaihoHeader()` は設計プレビュー・回答画面・印刷で共有している照会票ヘッダーなので、勝手に分岐させない
- 配布ファイルを汚さないため、**実行中に生成するDOMは必ず `[data-runtime]` を持つコンテナの中に入れる。** そこ以外に動的な要素を足すと、書き出したファイルに状態が焼き付く
- 同じ理由で、静的なマークアップ上の `<input>` には `setAttribute("value", ...)` を使わず `.value` プロパティだけを使う。`<select>` も `selected` 属性ではなく `.value` を使う
- エラーメッセージは「何が起きたか」と「どうすれば直るか」を書く。曖昧に謝らない
- キーボード操作でひととおり使えること、フォーカスが見えること、`prefers-reduced-motion` を尊重することは維持する

## 確認方法

変更のたびに、次の一巡が通ることを確かめてください。

1. エンジンHTMLを `file://` で開き、設問を数問作って配布用ファイルを書き出す
2. 書き出したファイルを `file://` で開き、回答モードで起動することを確認する
3. 回答を入力し、印刷プレビューで体裁を確認する
4. CSVを書き出す
5. 別の課名で同じ手順を繰り返し、2本のCSVを取りまとめモードに読み込ませて束ねる
6. 書き出したファイルからさらに配布用ファイルを書き出しても、内容が壊れないことを確認する(自己複製の多重適用)

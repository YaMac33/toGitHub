# ロードマップ

## Phase 0: 初期構築（完了）

- [x] 3社のプロバイダーを共通インターフェースで扱う（Anthropic / OpenAI / Gemini と、オフライン用の Mock）
- [x] APIキーを環境変数・`.env` で管理し、キーなしでも動くことの確認と、診断機能（`status`）
- [x] モデルカタログ（`models.yaml`）と、確認状況（verified / unverified）の明示
- [x] トークン使用量（実測値・推定値の区別）と推定料金（未設定と0の区別）の記録・集計
- [x] 役割とプロバイダーを分離したエージェント（Coding / Review / Research）
- [x] Sequential / Parallel ワークフローと TaskManager
- [x] CLI（status / providers / models / usage / ask / agents / workflows / run）
- [x] モックを使ったテスト（APIキー不要・通信なし）

## Phase 1: 実運用の準備

- [ ] OpenAI と Gemini の最新モデルIDを確認し、`status: verified` に更新する
- [ ] 全モデルの料金・コンテキスト長を `models.yaml` に登録する
- [ ] 各社1回ずつ、実際の API で疎通を確認する（短いプロンプトで）
- [ ] 予算上限（`budget.enforce`）を運用し始める。また、料金未設定のモデルを使うときに警告する
- [ ] モデルの最大出力トークン数を超える指定を検知する

## Phase 2: 対話機能の強化

- [ ] ストリーミング出力（`generate_stream`）
- [ ] 会話履歴の保持（`ask --session`）
- [ ] プロンプトテンプレート（`prompts/` ディレクトリ）
- [ ] ファイルを入力にできるようにする（`ask --file src/foo.py`）。コードレビューで使う
- [ ] 実行結果（ワークフローの出力）を Markdown で保存する
- [ ] キャッシュ・バッチ料金を考慮した料金計算

## Phase 3: マルチエージェント化

- [ ] ワークフローの条件分岐（例: レビューで「重大」の指摘があれば、修正ステップに戻す）。反復回数には上限を設ける
- [ ] Parallel の結果の統合（合議・比較表を作る「統合エージェント」）
- [ ] 1つの指示から、ワークフローを自動で選んで組み立てるオーケストレーター
- [ ] 人による承認ステップ（危険な操作や、料金が高くなる処理の前に止める）
- [ ] ツール呼び出し（Web検索、リポジトリ検索など）に対応する。まずは Research Agent から
- [ ] TaskManager の永続化（SQLite）と、中断したワークフローの再開

## Phase 4: 外部CLIエージェントとの連携

- [ ] Claude Code / Codex CLI / Gemini CLI をサブプロセスとして起動するアダプター（`ExternalCLIAgent.run`）
  - 各ツールは、自分自身の認証で動かす。このアプリからは認証情報に触れない
  - 作業ディレクトリの制限、実行前の承認、タイムアウトを必須にする
- [ ] APIエージェント（設計・レビュー）と外部CLIエージェント（実装）の協調ワークフロー
- [ ] Git の作業ブランチ・worktree で隔離して実行し、差分を確認してから取り込む

## Phase 5: UI

- [ ] Web UI（FastAPI など）。Orchestrator をそのまま使う
- [ ] 利用料金のダッシュボード（月別・プロバイダー別・モデル別）
- [ ] ワークフローの進捗表示（TaskManager の購読）

## 方針

- 安全性を優先する。自律的なファイル編集、外部への公開、push は、必ず利用者の承認を経る
- 新しい機能もモックでテストでき、APIキーなしで CI を通せる状態を保つ
- 依存は必要になってから追加する
